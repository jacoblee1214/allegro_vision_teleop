# 이미 한 번 받아 본 분을 위한 업데이트

전에 이 저장소를 받아서 돌려본 적이 있고, 새 UI·압력센서 화면과 저장소 안으로 들어온 리타게팅까지
쓰려는 경우입니다. 처음 받는 분은 [`../README.md`](../README.md) 를, 프로젝트를 통째로 이어받는
분은 [`HANDOVER.md`](HANDOVER.md) 를 보세요.

이 문서를 그쪽 Claude Code 에 그대로 넣어도 됩니다.

---

## 1. 올리기

```bash
cd <저장소>
git pull
./tools/setup.sh --no-apt
```

`pip` 목록은 그대로지만, **리타게팅이 저장소 안(`retarget/`)으로 들어오면서 전용 가상환경
`.venv-retarget` 이 생겼습니다.** `setup.sh` 가 만듭니다. 전에 필요했던 사내 MANUS 텔레옵 프로젝트는
이제 **필요 없습니다** — 최적화는 공개 라이브러리
[`dex_retargeting`](https://github.com/dexsuite/dex-retargeting)(MIT)이 하고, 손끝 위치와 접촉
거리는 이 저장소의 메쉬에서 측정한 값입니다.

가상환경이 둘인 이유는 numpy 입니다. `dex_retargeting` 과 pinocchio 는 2.x, mediapipe 는 1.x 를
요구해서 한 환경에 둘 수 없습니다. 리타게팅만 별도 프로세스로 돌고 ROS 토픽으로 이야기합니다.

## 2. 핀칭 확인 (로봇 없이)

```bash
.venv-retarget/bin/python tools/check_pinch.py
```

로봇을 여러 자세로 세워 그 손의 마디·손끝 위치를 읽고, 작업자 크기로 줄여 다시 리타게팅에 넣습니다.
나온 관절각이 손끝을 원래 자리로 되돌려 놓으면 통과입니다.

```
           pose   asked for   robot did    error   surfaces
          pinch      8.7 mm     18.4 mm   +9.7 mm    -0.8 mm
      open hand    166.8 mm    164.6 mm   -2.2 mm  +145.4 mm
```

`surfaces` 가 0 근처면 핀치가 실제로 맞닿는다는 뜻입니다.

## 3. 실행

```bash
./run_dashboard.sh                 # 실물, 연결된 손 자동 탐색 (오른손 우선)
./run_dashboard.sh --hand left
./run_dashboard.sh sim             # 로봇 없이 화면만
```

`run_dashboard.sh` 는 이제 v3 로 갑니다. 예전 동작은 `--v2`, `--v1`.

## 4. 새로 보이는 것

- 가운데 **압력센서 패널**: V6 손바닥 그림 위에 18채널 접촉 압력(kPa)
- 검은 배경과 머리말
- **T** 기준값 다시 잡기(손에 아무것도 닿지 않은 상태에서), **N** 채널 번호 표시
- 원익 로고 파일은 상표라 저장소에 없습니다. 머리말에 로고만 안 보이고 나머지는 정상입니다.

채널 배치는 손가락마다 **손끝 → 가운데 마디 → 뿌리 마디**(엄지 0~2, 검지 3~5, 중지 6~8, 약지 9~11,
소지 12~14), 손바닥은 15 = 위쪽 검지 쪽, 16 = 위쪽 소지 쪽, 17 = 아래쪽입니다. **N** 으로 번호를 켜고
패드를 하나씩 눌러 맞는지 한 번 보시길 권합니다. 500 hPa 아래로 읽히는 채널은 신호 없음(회색 `--`)입니다.

**패널이 비어 있으면** 드라이버 토픽을 못 찾은 것입니다.

```bash
ros2 topic list | grep tactile     # ...tactile_pressures 가 있어야 합니다
```

이름이 다르면 `--tactile-topic` 으로 직접 주고, 토픽 자체가 없으면 드라이버가 예전 빌드입니다.

## 5. 손이 다른 개체면 확인할 것 두 가지

아래 두 값은 **저희 쪽 실물에서 측정해 맞춘 것**이라 다른 손에서는 다를 수 있습니다. 오른손은 원익
공식 URDF 와 완전히 같아서 확인할 것이 없고, 왼손만 해당됩니다.

### 5.1 왼손 MCP 영점 (`joint11/21/31/41`)

저희 손은 손가락을 편 상태에서 **0** 을 읽어서 보정 없이 씁니다(기본값).

```bash
# 텔레옵을 끄고(토크 off) 손가락을 편 상태에서
./tools/check_hand.py <왼손 주소 끝자리>
```

그 값이 0 근처면 그대로 두고, −1.57 근처면 켜 주세요.

```bash
./run_dashboard.sh --hand left --left-mcp-offset -1.5708
```

틀렸을 때 증상: 실물은 폈는데 RViz 에서 손가락이 90° 굽어 보이고, MCP 네 관절이 똑같은 effort 로
포화된 채 전혀 굽지 않습니다.

### 5.2 왼손 벌림 관절 (`joint10/20/30/40`)

저장소의 `urdf/allegro_hand_v6_left.urdf` 는 이 네 관절만 원익 공식 URDF 와 축 부호가 반대입니다.
저희 왼손이 그렇게 측정돼서 맞춘 것이고, 근거는 파일 맨 위에 있습니다.

토크를 끄고 손가락을 좌우로 벌리며 엔코더를 읽어 보세요. 검지(`joint10`)가 **+1.3 쪽**으로 가면 지금
파일이 맞고, **−1.3 쪽**으로 가면 그 손은 공식 URDF 가 맞으므로 드라이버 패키지의 왼손 URDF 를 그대로
쓰면 됩니다.

## 6. RViz 에 메쉬가 안 보이면

왼손은 `meshes/left/` 를 씁니다. 드라이버 소스에 그 폴더가 없으면
`Could not load resource .../left/*.STL` 이 뜹니다. 원익 최신 배포본에서 받아 넣고 드라이버
워크스페이스를 다시 빌드하세요.

## 7. 지킬 것

- **원익 드라이버 패키지는 수정하지 않습니다.** 차이는 이 저장소의 `launch/` 와 `urdf/` 에서 흡수합니다.
- 실기 점검은 읽기 전용(`tools/check_hand.py`)으로 먼저 합니다. 로봇을 움직이기 전에 알리세요.
- **손은 Modbus 연결을 하나만 받습니다.** 다른 세션이 잡고 있으면 탐색에 보이지 않습니다
  (`ss -tn | grep 502` 로 확인).
