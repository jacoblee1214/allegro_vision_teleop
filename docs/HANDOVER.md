# 인수인계 — Allegro Hand V6 비전 텔레오퍼레이션

2026-10-08 기준. 이 저장소를 이어받아 돌리고, 양손 모드까지 붙이는 데 필요한 것만 적었습니다.

---

## 1. 이게 뭐고 어디에 쓰이나

웹캠 하나로 사람 손을 보고, 같은 손 모양을 Allegro Hand V6(5손가락 20관절)로 재현합니다. 깊이 카메라나 글러브 없이 RGB 한 장으로 돕니다.

더 큰 목표는 이것입니다.

> 사람이 작업하는 영상을 VLM이 이해하고, **xArm7 두 대에 왼손·오른손이 달린 양팔 로봇**이 같은 작업을 수행한다.

이 저장소는 그중 **손 부분의 입력 경로**입니다. 사람 손 → 로봇 손 변환이 실제로 되는지, 어떤 데이터가 필요한지를 실기로 확인하는 자리이고, 여기서 모은 손 데이터가 뒤쪽 학습에 쓰입니다. 팔(xArm7)과 VLM은 아직 이 저장소에 없습니다.

```
웹캠 ─ MediaPipe(21점) ─ DexPilot 리타게팅 ─ 브리지(100 Hz) ─ ros2_control ─ Modbus TCP ─ 손
                                                     └ RViz / 대시보드(압력 18채널)
```

## 2. 이 PC 환경

**도커를 쓰지 않습니다.** Ubuntu 24.04 + ROS 2 Jazzy 네이티브입니다. (예전 Humble/도커 버전은 `humble/` 에 동결해 뒀습니다. 컨테이너 `ros_humble_dev` 안에서만 돌아갑니다.)

| 무엇 | 어디 |
|---|---|
| 이 저장소 | `~/allegro_vision_teleop` (예전 `~/humble_ws/allegro_vision_teleop` 은 바로가기) |
| 원익 드라이버 작업공간 | `~/v6f_manuse_teleoperation` (빌드됨) |
| 드라이버 **원본** 소스 | `~/hands` (원익 공식 배포, 2026-10-02) |
| MANUS 텔레옵 프로젝트 | `~/V6_Teleoperation` (DexPilot 리타게팅 코어를 **복사하지 않고 그 경로에서 읽습니다**) |
| 저장소 가상환경 | `~/allegro_vision_teleop/.venv` (mediapipe, numpy 1.26) |
| 리타게팅 가상환경 | `~/V6_Teleoperation/.venv` (dex_retargeting, numpy 2.x) |

가상환경이 둘인 이유는 numpy 버전이 충돌해서입니다. mediapipe는 1.x, dex_retargeting은 2.x를 씁니다. 리타게팅만 별도 프로세스로 돕니다.

### 처음부터 다시 깔 때

`README.md` 의 "환경 설정" 을 따르면 됩니다. 이 PC에서 실제로 걸렸던 것 세 가지만 미리 적습니다.

1. **conda**: 셸에 `VIRTUAL_ENV=~/miniforge3` 가 잡혀 있으면 CMake가 conda 파이썬을 골라 `No module named 'catkin_pkg'` 로 빌드가 죽습니다. 빌드할 때만 변수를 빼세요.
   ```bash
   cd ~/v6f_manuse_teleoperation
   env -u VIRTUAL_ENV -u CONDA_PREFIX PATH=$(echo $PATH | tr ':' '\n' | grep -v miniforge | paste -sd:) \
     bash -c 'source /opt/ros/jazzy/setup.bash && colcon build --symlink-install --base-paths src'
   ```
2. **`--base-paths src`**: 작업공간 안에 `V6_Teleoperation` 바로가기가 있어서, 이게 없으면 colcon이 그 안의 URDF 패키지까지 빌드하려다 실패합니다.
3. **빠진 파일**: 드라이버 소스에 빈 `allegro_hand_v6_description/usd/` 폴더가 없으면 설치 단계에서 죽습니다. `mkdir` 로 만드세요.

평소에는 다시 빌드할 일이 없습니다. 드라이버 소스를 바꿀 때만 합니다.

## 3. 실행

```bash
cd ~/allegro_vision_teleop
./run_dashboard.sh                 # 실물. 연결된 손을 찾고 오른손을 먼저 고른다
./run_dashboard.sh --hand left     # 왼손 지정
./run_dashboard.sh sim             # 로봇 없이
./tools/check_hand.py <주소 끝자리>  # 통신만 점검 (읽기 전용, 로봇 안 움직임)
```

떨림이 거슬리면 `--smooth 9 --ema 0.2`, 더 민첩하게는 `--smooth 3 --ema 0.5`.

화면 단축키: **C** 클러치(멈춤), **T** 압력 기준값 재측정, **N** 압력 채널 번호, **Q** 종료. 실물에서 **H**(손 바꾸기)는 비활성입니다 — 이유는 5장에.

## 4. 하드웨어 사실 (실측으로 확인된 것)

이 네 가지는 코드만 읽어서는 알 수 없고, 틀리면 바로 오동작으로 나타납니다.

### 4.1 네트워크

PC와 두 손은 같은 서브넷에 둡니다. 주소와 인터페이스는 `config/teleop.env` 의 `PC_IP`, `ETH_IFACE`, `HAND_IP` 에 있습니다 (이 작업대의 실제 값은 그 파일과 사내 문서를 보세요). 같은 망에 다른 Modbus 장비가 있어서, 런처는 펌웨어 레지스터와 손 종류를 읽어 알레그로 핸드인지 **검증**한 뒤 고릅니다.

**손은 Modbus 연결을 하나만 받습니다.** 다른 세션이 잡고 있으면 탐색에 아예 안 보입니다. `ss -tn | grep 502` 로 확인하세요.

펌웨어: 왼손 `0x0103`, 오른손 `0x0300`. **세대가 다릅니다.** 아래 두 항목이 여기서 비롯된 것으로 보입니다.

### 4.2 왼손 벌림 관절 부호 — 공식 URDF와 다름

`joint10/20/30/40`(손가락 좌우 벌림)에서 **공식 드라이버 URDF가 이 왼손과 맞지 않습니다.**

손가락을 손으로 벌려 엔코더를 읽어 확인했습니다(명령 미전송).

| 관절 | 실측 | 공식 왼손 URDF | 저장소가 쓰는 값 |
|---|---|---|---|
| joint10 | −0.40 ~ **+1.39** | −1.31 ~ +0.38 ✗ | −0.38 ~ +1.31 ✓ |
| joint30 | **−1.28** ~ +0.41 | −0.38 ~ +1.31 ✗ | −1.31 ~ +0.38 ✓ |

즉 **이 왼손은 오른손과 같은 부호**를 씁니다. 공식 URDF는 좌우를 거울처럼 기술해 놨는데 하드웨어가 그걸 따르지 않습니다. 드라이버는 레지스터 ↔ 라디안 변환에 양수 배율(`PUL2RAD`)만 쓰고 부호를 건드리지 않으므로, 읽은 값이 곧 URDF 관절값입니다.

그래서 `urdf/allegro_hand_v6_left.urdf` 의 이 네 관절만 공식과 다르게 두고, 파일 맨 위에 근거를 적어 뒀습니다. **드라이버를 새로 받아도 이 부분은 덮어쓰지 마세요.** 오른손은 공식과 완전히 같습니다.

### 4.3 왼손 MCP 영점 — 9월과 달라졌음

`joint11/21/31/41` 은 **손가락을 편 상태에서 0을 읽습니다**(URDF 그대로). 보정이 필요 없고 기본값도 보정 없음입니다.

9월에는 이 값이 −π/2 였고, 그에 맞춰 브리지가 명령에서 90°를 빼고 상태에 더하고 있었습니다. 그 보정이 남아 있던 동안 편 손을 그리라는 명령이 −1.57로 나가 관절 한계(−0.07)에 걸렸고, 네 모터가 effort −0.23으로 포화된 채 스토퍼를 밀고 있었습니다. **왼손 MCP가 아예 굽지 않는 상태**였습니다.

지금은 설정값입니다. 영점이 90° 틀어진 손을 만나면 되살리세요.

```bash
./run_dashboard.sh --hand left --left-mcp-offset -1.5708
```

**확인 방법**: 텔레옵을 끄고(토크 off) 손가락을 편 상태에서 `./tools/check_hand.py <왼손 주소 끝자리>` 를 읽습니다. 그때 나오는 값이 곧 오프셋입니다. 0 근처면 보정하지 마세요.

### 4.4 압력센서 18채널 배치

손가락마다 **손끝 → 가운데 마디 → 뿌리 쪽 마디** 순서입니다. 엄지 0~2, 검지 3~5, 중지 6~8, 약지 9~11, 소지 12~14. 손바닥은 15 = 위쪽 검지 쪽, 16 = 위쪽 소지 쪽, 17 = 아래쪽.

오른손에서 패드를 하나씩 눌러 실측했습니다(2026-10-08). 왼손은 좌우 반전해 쓰고 따로 눌러 보지 않았습니다. 좌표는 `assets/v6_tactile_layout.json`, 화면에서 **N** 을 누르면 채널 번호가 보입니다.

**이 오른손은 14번(소지 뿌리 쪽)이 0을 읽습니다.** 센서나 배선 문제로 보이고, 화면에는 회색 `--` 로 나옵니다.

단위는 접촉 압력 kPa입니다. 센서가 대기압(1013~1024 hPa)을 읽으므로 시작할 때의 값을 기준으로 뺍니다. 손에 뭔가 닿은 채로 시작했으면 **T** 로 다시 잡으세요.

## 6. 양손 모드 — 아직 안 한 일

전 계층을 건드려야 해서 작은 추가가 아닙니다. 순서대로 하고 각 단계마다 확인하는 걸 권합니다.

1. **드라이버 2개**: 원익 패키지에 양손 설정이 없습니다(`config/single_hand` 만). 네임스페이스를 `/left`, `/right` 로 나눠 `controller_manager` 를 두 벌 띄우고 IP를 각각 줍니다. 관절 이름 충돌은 xacro의 `ah_prefix` 로 풉니다. 컨트롤러 yaml도 손별로 필요합니다.
   - 확인: `ros2 control list_controllers` 가 양쪽에서 각각 보이고, 두 손이 동시에 `/joint_states` 를 낸다.
2. **비전**: 지금 `max_num_hands=1` 입니다(`teleop_dashboard_v3.py`). 2로 올리고 MediaPipe의 handedness로 좌우를 갈라 토픽을 나눕니다. 화면 미러링 때문에 좌우가 뒤집혀 들어오는 점에 주의하세요(`--no-mirror` 참고).
   - 확인: 두 손을 들었을 때 좌우 토픽이 각각 나오고, 한 손만 들면 그쪽만 나온다.
3. **리타게팅 2개**: DexPilot 모델을 손별로 하나씩. 한 프레임 2 ms 수준이라 부하는 문제없습니다. 왼손 설정은 `~/V6_Teleoperation/.../v6f_left_dexpilot.yml` 을 씁니다.
4. **브리지 2개**: `--hand` 와 토픽만 나누면 됩니다. MCP 영점 보정은 왼손에만 들어갑니다(4.3).
5. **RViz**: 로봇 두 대를 한 장면에 올리려면 링크·프레임 이름을 손별로 접두사로 나눠야 합니다. `urdf/allegro_hand.urdf.xacro` 가 이미 손 모델을 저장소에서 읽으므로 여기에 접두사를 붙이면 됩니다.
6. **대시보드**: 압력 패널 2개, 손 표시 2개, 카메라 화면 하나에 두 손.

양손이 모두 연결된 상태에서 하는 게 좋습니다. 한쪽씩 먼저 돌려 보고 합치세요.

## 7. 원익에 물어볼 것

1. **왼손 벌림 축 부호** (4.2). 공식 왼손 URDF가 실물과 반대입니다. 측정값과 "드라이버는 부호 변환을 하지 않는다"는 코드 근거를 같이 보내면 됩니다. 펌웨어 세대 차이(`0x0103` vs `0x0300`)가 원인인지 확인이 필요합니다.
2. **왼손 MCP 영점** (4.3). 9월과 달라졌습니다. 공장 기본값인지, 누가 다시 영점을 잡은 것인지.
3. **오른손 14번 압력 채널 무신호** (4.4).

1번이 해결되면 `urdf/allegro_hand_v6_left.urdf` 의 예외와 `urdf/allegro_hand.urdf.xacro` 를 지우고 공식 URDF를 그대로 쓸 수 있습니다.

## 8. 구조

최신은 **v3** 이고 `run_dashboard.sh` 가 항상 최신을 가리킵니다. `--v2`, `--v1` 로 예전 버전을 쓸 수 있습니다.

| 파일 | 하는 일 |
|---|---|
| `run_dashboard.sh` | 평소 쓰는 입구. 최신(v3)으로 넘긴다 |
| `run_teleop_v3.sh` | 손 탐색, 노드 기동, 인자 전달 |
| `teleop_dashboard_v3.py` | 카메라·MediaPipe·화면·압력 패널 |
| `retargeting_node_v3.py` | DexPilot 리타게팅 + 입력 평활화(중앙값 5 + EMA 0.3) |
| `sim_bridge_node.py` | 100 Hz 명령 송출, 왼손 MCP 영점 보정 |
| `tactile_panel.py` | 압력 18채널 표시 |
| `launch/allegro_hand_bringup.launch.py` | 드라이버 기동 + RViz |
| `urdf/allegro_hand.urdf.xacro` | 드라이버 bring-up xacro와 같되 손 모델만 저장소 것을 쓴다 |
| `tools/` | `setup.sh`, `check_hand.py`, 카메라 탐지, 배경 렌더 |
| `humble/` | 예전 도커/Humble 버전 (동결) |

관련 문서: `README.md`(설치·실행 전부), `docs/dexpilot_retargeting_v2.md`(리타게팅이 왜 이렇게 생겼는지), `docs/porting_notes.md`(도커→네이티브 포팅).

## 9. 주의

- **드라이버 패키지는 수정하지 않습니다.** 차이는 `launch/` 와 `urdf/` 에서 흡수합니다. 4.2의 왼손 URDF가 유일한 예외이고 이유를 파일에 적어 뒀습니다.
- `~/V6_Teleoperation` 은 동료의 MANUS 글러브 텔레옵 프로젝트입니다. 리타게팅 코어를 그 경로에서 읽기만 하고 **수정하지 않습니다.** 그 폴더가 없으면 v2/v3가 돌지 않습니다.
- 실물에서 손가락이 명령을 안 따라가면 effort를 보세요. 네 관절이 똑같은 값으로 포화돼 있으면 한계에 밀어붙이는 중입니다(4.3이 그 사례).
- 원익 로고(`assets/wonik_logo.png`)는 상표라 git에 올리지 않습니다. 로컬에만 둡니다.
